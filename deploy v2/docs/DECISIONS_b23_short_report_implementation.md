## §1 — الميكانيكا الأربع (العقد)

1. **`valuation.scenarios`** لكل فيلا/بيت مُقيَّم: `as_is` / `renovated_excellent` / `luxury_finish` / `teardown_land` — بالحاسبات النقية القائمة (DRC b11/b13 `_cost_approach_value` + أرضية B-1 `_villa_value_floor` + شريحة هدم b4) على السياق المجلوب؛ **صفر GIS جديد**؛ مفتاح شقيق، العنوان غير ممسوس.
2. **`report_ref` = `TH-{YYYYMMDD}-{ZZSSSBBB}`** (+`-{4hex}` من بصمة مدخلات التحسين إن وُجدت؛ احتياط `P{pin}` للأرض).
3. **`report_fp` = HMAC-SHA256(HMAC_REPORT_KEY, "v1|عنوان|تاريخ|محرك|amount|low|high|rule")[:12]** — تطبيع `\s+` لكل حقل قبل الدمج؛ المفتاح Heroku config؛ **DORMANT (None) بلا مفتاح** (#62 — ليس هاش حقول منخفضة الإنتروبيا).
4. **`GET /verify`** — حمولة+بصمة → صفحة ✓/✗ تعرض الحقول؛ يعيد الاحتساب بالدالتين المشتركتين (لا انجراف)؛ مقارنة ثابتة-الزمن؛ **بلا تخزين**؛ rate-limit بصيغة السلسلة (درس slowapi #35).

## §2 — توقيع D1–D8 (بصيغة D3 المعدّلة: الافتراض قابل للتعديل داخل السطر)

- **D1 — مجموعة السيناريوهات.** 4 مفاتيح ثابتة، فيلا/بيت فقط (`_TEARDOWN_ASSET_TYPES`)، عبر الحاسبات النقية، صفر GIS، العنوان مجمَّد. *(الافتراض القابل للتعديل: المفاتيح الأربعة — يمكن إضافة/حذف سيناريو لاحقاً.)*
- **D2 — معاملات DRC.** `renovated_excellent` = تشطيب `good` (RCN 2500) + حالة `excellent` (عقوبة −2)؛ `luxury_finish` = تشطيب `luxury` (3500) + `excellent`. *(الافتراض: سلّم RCN + عقوبة الحالة — مأخوذ من b13؛ قابل للمعايرة.)*
- **D3 — الهدم.** `teardown_land = max(land_floor − demo, 0)`؛ `demo = clamp(240×BUA, 100k, 150k)` (شريحة b4). *(الافتراض: شريحة الهدم — معايَرة PO.)*
- **D4 — نطاق السيناريو.** DRC: `value ±10%`؛ teardown: `low = value×0.88`, `high = land_floor`. *(الافتراض: ±10% — عرض-فقط، قابل للتضييق.)*
- **D5 — report_ref.** `TH-YYYYMMDD-ZZSSSBBB`؛ zone/street/building بأصفار-بادئة (02/03/03)؛ `+4hex` = SHA-256(مدخلات التحسين المرتّبة)[:4] (هاش عادي — تمييز عرضي لا أمان)؛ احتياط `P{pin}`. *(الافتراض: تنسيق الـ ref + طول الـ4hex.)*
- **D6 — report_fp.** HMAC-SHA256[:12] على القانوني `v1|addr|date|engine|amount|low|high|rule`، تطبيع `\s+`+strip لكل حقل؛ **DORMANT بلا مفتاح**؛ القيم تُحوَّل نصاً اتساقاً مع جولة /verify (int 2400000 ≡ "2400000"). *(الافتراض: الحقول الثمانية + طول البصمة [:12].)*
- **D7 — /verify.** GET؛ يعيد الاحتساب بـ `_report_canonical`+`_report_fingerprint` المستوردتين من المحرك (لا انجراف)؛ `hmac.compare_digest`؛ HTML ✓/✗/«غير مُفعَّل»؛ بلا تخزين؛ rate-limit `";".join(RATE_LIMIT_LIST)`. *(الافتراض: GET بمعاملات الاستعلام — يمكن لاحقاً QR/token مضغوط.)*
- **D8 — المفتاح (#55 audit).** `HMAC_REPORT_KEY` في Heroku config؛ غيابه ⇒ `report_fp=None` + الرابط لا يُرسم + /verify «غير مُفعَّل»؛ السيناريوهات + `report_ref` مستقلّة عن المفتاح. *(الافتراض: مفتاح عشوائي 64hex؛ تدويره = إبطال البصمات القديمة — مقبول لأداة نزاهة بلا تخزين.)*
