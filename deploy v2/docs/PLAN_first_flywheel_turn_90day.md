# Plan — The First Flywheel Turn (90 days, single operator)

> **Date:** 2026-06-20 · **Type:** Strategic action plan (prescriptive companion to
> `docs/BOARD_REVIEW_business_panel_v1.md`).
> **Owner:** Anas (solo operator). **Scope:** demand + data + moat — NOT engine accuracy.
> **Thesis:** one motion closes the top three board-consensus gaps — *no feedback loop, no
> distribution, no moat* — by going B2B with the ±1% bank-report proof, capturing real sale
> outcomes from every engagement, and starting the Decision-28/2023 license now.

## Why this and not "more accuracy sprints"

The board's verdict: ~60 sprints built the supply side; the company doesn't exist because the
demand side, the data loop, and the moat are all at ~zero. The accuracy work has a hard ceiling
anyway — `R7` (condition/built-type calibration) is **parked on n≥20 documented sales**, and that
corpus is at ~1 (V001/TD-93317). You cannot out-engineer a missing dataset. The only way past the
ceiling **and** to a business is to put the engine in front of people who transact property
repeatedly and *hold* the outcome data. That is the same motion.

## Constraints this plan respects

- **Solo operator.** No sales team, no hires. Every action is achievable by one person.
- **Live product, not a "beta."** thammen.qa works today — the gap is users, not launch.
- **Cannot charge yet** (Decision 28/2023 — التثمين is regulated; license precedes paid valuation).
  So the 90-day money goal is a signed **LOI / paid-pilot intent**, not collected revenue.
- **Real assets in hand:** the live engine, the ±1% TD-93317 reproduction, Qatari nationality +
  local real-estate network, RICS-framed defensibility.

## The 90-day sequence

### Days 0–30 — Package the proof + instrument the loop
**Track A.** Build ONE artifact: a 1-page "Thammen for institutions" demo built around the
**TD-93317 ±1% reproduction** (their certified valuer's number vs. the engine's, side by side,
in seconds, free of the slow manual chain). Identify 5–8 realistic first targets — order of ease:
(1) an independent **licensed valuation firm** (they feel the manual-labour pain most and can
co-sign credibility), (2) a **brokerage** desk that prices listings daily, (3) a **bank** mortgage
/ valuation unit. Use the existing network first; warm intro > cold every time.

**Track B.** Make capture frictionless and *always-on*: the operator email-copy memory already
archives every report — add a single "هل لديك سعر بيع فعليّ أو تقييم معتمد؟" intake path
(WhatsApp/email/one form field) so any real figure lands in `validate_gt_sheet.py` →
`VALIDATION_LOG.md`. Define the **one input metric** to watch weekly: *documented ground-truth
figures captured.* (Bezos: measure the input, not the output.)

**Track C.** Send the Decision-28/2023 inquiry (the held `docs/Aqarat_Enquiry_DRAFT_hold.md`).
Question framed positively: "what is the path to license an automated valuation service?" — you
want to be *first in the queue*, and the answer shapes everything downstream. This is slow; start
it Day 1 so it runs in the background.

### Days 31–60 — First pilots + first data
**Track A.** Get the engine in front of **1–3** prospects on *their own* properties — live, in the
room/call, on real addresses they already know the answer to. The win condition is not a contract;
it's the prospect saying *"that's close"* on a property where they hold the truth. Each session is
also a Track-B capture (they'll volunteer the real figure to test you).

**Track B.** Target **5+ documented** figures by Day 60 (institutional pilots are the fastest
source — they have confirmed sales and certified valuations on hand). Each one runs through the
existing kit. Watch the R7 residual move on real data for the first time. This is the moment the
flywheel turns.

**Track C.** Log the Aqarat response; if licensing requires a corporate vehicle / partner valuer,
scope that now (it pairs naturally with the Track-A valuation-firm prospect — a licensed partner
solves both the moat and the co-sign).

### Days 61–90 — Convert to intent + file the moat
**Track A.** Convert at least **one** pilot into a signed **LOI or paid-pilot intent** (paid
activates on license per Track C). The ask is small and concrete: "run your next N valuations
through Thammen as a cross-check; if it holds, we formalize on license."
**Track B.** Push toward **8–10 documented** figures — visibly approaching the n≥20 that unparks
B-2 (the real accuracy unlock, now justified by real demand).
**Track C.** Have the licensing path *in writing*: requirements, timeline, partner structure. Even
"here is the 6-month path" is a moat you can now articulate to investors/partners.

## What to STOP doing (the honest part)

- **Pause engine micro-sprints** (b61, the Arabic-string polish, the decomposition-recompute gap,
  more keystone slices). They serve an audience of ~zero and chase accuracy you cannot calibrate
  without data this plan *generates*. Bank ~2 days/week of the same energy into Tracks A/B/C.
- **Don't build apartment support speculatively.** Coverage gap #3 is real, but build it when a
  B2B prospect *asks* and brings the data — demand-pulled, not supply-pushed.
- **Don't perfect the consumer UI further** until users exist to justify it.

## Risks & honest caveats

- **Network reality:** the prior data feeds (the secretary source, the Gardenia brokerage) are
  closed. Track A assumes a *new* warm intro can be found; if the network is genuinely cold, the
  first 30 days are about rebuilding one relationship, and the timeline stretches.
- **Aqarat may be slow or restrictive.** If licensing is hard, the B2B motion can still run as a
  free cross-check tool (no charging) while capturing data — the flywheel turns regardless; only
  revenue waits.
- **Solo bandwidth.** Three tracks for one person is tight. If forced to pick one: **Track B
  (data capture)** — it's the existential gap and it rides on infrastructure you already have.
